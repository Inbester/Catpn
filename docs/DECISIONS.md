# Project decisions (Quanta — crypto charting / strategy platform)
- Chart view (menu 1): APPROVED by user on 2026-09-25. Reference mockups: chart-1..6 PNGs.
  - Theme A (graphite dark) default + Theme B (paper light) alt. 8px grid, Inter + JetBrains Mono tabular numbers.
  - App rail 56px (Chart, Strategy, Forward test, Research, Alerts, Bot), drawing toolbar 48px, watchlist 320px w/ Watchlist|Objects tabs.
  - Drawing tools per TradingView groups, floating object toolbar w/ add-alert, indicator legend eye/gear/x, pane controls, object tree, templates.
  - Candle countdown under last-price label (server time, UTC boundaries), position/TP/SL/liq/alert lines, bottom range bar, %/log/auto, settings dialog w/ 6 tabs.
- Pending: UI language, exchange adapter approach (Bitunix restricts Iran), formula authoring (recommended: safe DSL + visual builder).
- Backend: Python FastAPI, Postgres+Timescale, Redis, isolated execution service.
- Strategy menu (menu 2) proposed 2026-09-25 (awaiting approval): strategy-1..3 PNGs.
  - Builder: strategy list | editor (Inputs w/ optimizable params, Long/Short entry condition rows ALL/ANY + OR groups, Exit & risk grid, formula view) | Backtest panel (symbol, TF, Jalali/Gregorian period, capital, isolated/cross, leverage, margin %, Bitunix fees auto, slippage, historical funding, mark-price liquidation, fill next bar open, 1m bar magnifier).
  - Results tabs: Overview, Performance, Trades analysis, List of trades, Costs & liquidation, Properties. Versions locked by hash; "Forward test" CTA.
- Builder "Discover" tab (2026-09-25): auto-detect series scales; primitives = unary (slope, turn, N-bar extreme, neutral level, level cross), pairwise same-scale (position, cross, spread), price divergence (regular/hidden ±). Example 3-line indicator: 54 primitives (18 filters/36 triggers) -> 26,289 raw combos<=3 -> 5,324 valid -> x2 sides x4 horizons = 42,592 tests; BH-FDR 5% + 70/30 OOS; returns shown after Bitunix costs.
- Discover multi-indicator + client compute (2026-09-25): sources chips (Price, EMA20/50, RSI14, MyIndicator) -> 7 series, 4 scale groups, 112 primitives (48F/64T), 234,248 raw, 69,828 valid, 558,624 tests; options max-per-rule, mix>=2 indicators (59,348 rules).
  - Compute: compact widget in footer (device, CPU/GPU/RAM bars) + popover: engine This browser | Local agent | Cloud; detected via hardwareConcurrency, WebGPU adapter.info, deviceMemory (coarse), COOP/COEP shared memory, OPFS cache; sliders CPU workers %, GPU duty cycle %, RAM budget; reserve 1 core; battery throttle; live usage = this app only.
- Global Jobs (2026-09-25): progress ring in app rail above Settings on every menu (% + queued badge), click -> Jobs tray (Running w/ tests/s & CPU/GPU/RAM, Queued, Paused w/ checkpoint resume, Finished w/ Open). Completion toast + browser notification. Jobs live outside page components (worker/app-level store), checkpointed to IndexedDB; tab close pauses browser jobs; local agent/cloud continue.
- Forward test menu (2026-09-25, proposed): tabs Period vs period (user's idea: Farvardin 1404 ref vs 1405, frozen v3, MC 90% band from ref trades, verdict + regime explanation), Walk-forward (12 windows, 3m IS -> 1m OOS, Jalali months, WFE, chained OOS equity), Paper trading (live Bitunix feed, expectation cone, execution drift, promotion checklist -> Trading bot, 2FA override).
- Assumed: Local agent deferred to later phase (browser-first) unless user says otherwise.
- Persistence (2026-09-25): autosave everything (drawings per symbol/TF, indicators, panes, layouts, settings, strategy edits as draft versions, research/backtest results, UI state). Local-first (IndexedDB) + server sync; "Saved" status in top bar (Saving/Offline states); History tab in right sidebar (filter All/Chart/Strategy/Research/Settings, Restore, named versions, device sync); undo survives refresh; 90-day history, named forever.
- Drawdown panes required under every equity/comparison chart (backtest, period vs period incl. MC worst-case line + longest DD row, walk-forward per-window Max DD + chained underwater, paper trading live DD vs expected band + user limit).
- Research menu (2026-09-25, proposed): tabs Leverage & costs (iso vs cross matrix 1x-75x: exposure=margin%xlev, liq distance, net/yr, max DD, worst trade, liqs, costs/gross, risk of ruin; recommended = highest lev within user DD & ruin limits), Trade risk (MAE scatter w/ liquidation lines per leverage, deepest trades "survives up to Nx", holding time + funding), Robustness (param heatmap plateau, 1,000 reshuffled years, VaR/CVaR, Kelly/half-Kelly, stress tests: VIP3 fees, fees x2, slippage x3, funding +0.03%, remove best 5), Relationships (= Discover engine results), Risk report (CFO PDF summary).
- Research setup = interactive ranges (2026-09-25): margin % dual slider 0-100 (step), leverage dual slider 1..exchange max (log scale; BTCUSDT 200x per Bitunix, from get_trading_pairs maxLeverage + get_position_tiers), margin mode seg, fee tier dropdown with VIP0-8 fetched (multi-select compare, account tier detected), max DD budget dual slider, risk-of-ruin slider. Result: margin x leverage heatmap (in-budget outlined, outside dimmed/hatched, liq badges), recommendation = best net in budget with lowest leverage (equal exposure insight). Fixed chart card max leverage 125x -> 200x.
- Alerts menu (2026-09-25, proposed): list (Strategy/Price/Indicator/Risk/Market/System) + activity feed with per-destination delivery status & latency + Telegram preview; New alert form (source, events, bar-close vs tick, repeat, burst merge 10s, quiet hours silent, message template vars EN/FA + chart snapshot, destinations browser devices / Telegram DM, group, channel / webhook / email, test send); Channels page (one-time deep links start/startgroup, channel via admin "Post messages", QR, connected list, rate limits 1/s per chat 20/min per group w/ queue+merge, retries, privacy). Alerts evaluated server-side (fire when browser closed).
- Rail: active-alerts bell with count (green badge) under jobs ring on every page; popover groups active alerts by setup + next check times.
- SETUP concept (2026-09-25): named, colored bundle = strategy version (locked) + symbol + TF + params + exits + position (margin x lev, mode) + fee tier + risk budget + source research run. Created via "Save as setup" from Research; every menu (Backtest, Forward, Paper, Alerts, Bot) has a Setup picker in header showing pipeline status chips. Setups overview page (tab in Strategy menu): pipeline table per setup, exposure KPIs, conflict checks (same symbol in one-way mode -> hedge mode or sub-accounts), combined risk simulation.
- MENU ORDER (2026-09-26): Chart, Research (incl. strategy builder/Discover/setups), Test (backtest + forward + paper), Alerts, Trading bot, Resources, AI (AI menu TBD).
- Resources menu: Compute tab (Server vs This computer cards, live server specs CPU/RAM/GPU/storage, user share & queue, per-feature choice Server/This computer/Auto; alerts & bots locked to server; research footer widget shows active compute source). Network tab: WireGuard .conf upload (multi) or paste with format shown + validation (sections, base64 keys, host:port, CIDR), live test every 30s (handshake, ping, jitter, loss, speed, exit IP, quality bars), per-feature routing (chart data, research downloads, alerts/Telegram, AI) with failover. Trading bot order traffic locked to server static IP (API key IP whitelist) - NOT routable via VPN (also: Bitunix restricts Iran; no geo-restriction circumvention).
