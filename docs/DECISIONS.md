- LANGUAGE AND CALENDAR (2026-09-26, decided by user, supersedes D11's earlier default): the interface is English only and the calendar Gregorian only. Persian is not a second UI: resting the pointer on a word for ~1.4s opens a small window under that word with the Persian term and an explanation, in Vazirmatn (Google Fonts, Arabic subset). It must stay out of the user's way — no pointer events, dismissed by any move, scroll, key, click or blur, never over an input, and anchored to the word rather than the cursor so it cannot cover what is being pointed at. Consequences: the fa bundle, the Jalali converter and the RTL chrome were removed; forward-test presets are Gregorian months on UTC boundaries (Farvardin 1404 vs 1405 became March 2025 vs March 2026); locale and calendar are no longer settable through the preferences API. The one place Persian is still produced is alert message text, chosen per alert, because that is a message sent to the user's phone and not part of the interface.
- TRADING BOT MENU / D9 (2026-09-26, settled): three tabs — Bots (card per bot: setup name+colour, symbol/TF, state, current position, today's realised+unrealised P&L, orders today, and daily-loss and drawdown budgets drawn as bars), Keys (add flow shows the server's static IP to whitelist first, then verifies the key server-side: withdrawal permission refused outright, not-whitelisted refused with the IP repeated; afterwards only label + last four + fingerprint are ever shown), Activity (audit log: every order with clientId/request/response/latency, plus reconciliations, risk trips, and start/stop/kill with who). Kill switch lives in the menu header on every tab — stops every bot and cancels every open order, 2FA — because the moment you want it is the moment you do not want to pick from a list. States stopped -> armed -> running, and halted from any of them; halted carries its reason and only a human clears it, nothing un-halts itself. Pre-flight gates arming, each check shown with the figure it was judged on (same pattern as paper promotion): setup promoted from paper; key attached, no withdrawal permission, IP whitelisted; no other bot on the same symbol+account in one-way mode; intended size inside the exchange position tier at the chosen leverage; risk limits set and within equity; 2FA enabled. 2FA required to arm, to go live and to kill, and to raise a risk limit but not to lower one.
- KILL SWITCH SCOPE (2026-09-26, decided by user): the kill switch closes positions as well as cancelling orders. Order: halt every bot, cancel every open order, then close every open position with reduce-only market orders. Rationale: stopping the bots but leaving a leveraged position open is a pause, not a kill. The confirmation dialog states that positions will be closed at market, since that is a real cost at a bad moment and the user is choosing to pay it. Partial failures are reported per symbol rather than rolled back — a half-flattened account the user can see beats an error that hid what happened.
- EXCHANGE KEYS LIVE IN SETTINGS (2026-09-26, decided by user): the user supplies their own exchange API key, and it is entered in Settings rather than in a Keys tab inside the Trading bot menu. It belongs to the account, not to any one bot; one key serves every bot; and Settings is where a person goes to connect an outside service. The Trading bot menu drops to two tabs (Bots, Activity) and its create-bot flow picks from connected keys, linking to Settings to add one. Settings itself is specified for the first time here (SPEC §3.6): Account (name, password, 2FA enrolment + recovery codes), Sessions (devices, sign out everywhere), Exchange keys (static IP shown BEFORE the key field, server-side verification, label + last four + fingerprint afterwards, no delete while a bot uses it), Appearance. The 2FA part is not optional furniture: §3.5 requires 2FA to arm a bot, so without this page the trading bot cannot be used at all.
- TUNNELS ARE REAL AND CONTROLLED FROM THE WEB APP (2026-10-01, asked for by user): every imported WireGuard config runs on the server as its own wireproxy process (userspace WireGuard → loopback SOCKS5), started on first use, and Resources → Network shows and controls it — engine status, per-tunnel state (running / idle / failed with wireproxy's reason / off, plus "no traffic" when the last test got nothing back), an on/off switch, rename, real Test (exit IP, latency, jitter, loss, band), and per feature a first-choice and fallback tunnel, then the server. Failover happens at send time too: a tunnel whose process runs but carries nothing (no handshake) is found by the send that fails, passed over for 60s, and the message goes out by the next route. Alert delivery and test sends use that route and record which way each message went. Chosen over kernel WireGuard with policy routing because a proxy can only carry what it is handed: a wrong ip rule would silently move order traffic too, which SPEC §9 forbids. Exchange traffic stays locked to the server in three places (routes API, resolver, isolation test), and the exchange clients now ignore proxy environment variables, which they previously followed by default. AmneziaWG configs are refused unless an AmneziaWG build is configured, because plain WireGuard accepts them and never connects. The SPEC §3.6 "test every 30 seconds with handshake age" becomes on-demand tests at most every 25s with no handshake age — wireproxy does not expose it and an invented figure would be believed. Also fixed while wiring this: alert and paper bar times were 32-bit columns holding millisecond timestamps, so the first real alert firing failed to save; widened to bigint.
- DISCOVER INDICATOR PICKER (2026-10-01, asked for by user): Research → Relationships replaces the five fixed chips (EMA 20/50, SMA 50/200, RSI 14, MACD) with a picker over a catalog of ten — EMA, SMA, Bollinger, RSI, MACD, ROC, Stochastic, CCI, ATR, Volume — each with its own settings, each addable more than once (EMA 9 and EMA 21), up to eight per search. Most can be applied to another indicator instead of price (EMA of RSI, SMA of volume); a smoothing indicator inherits its input's scale so it is compared with that input and never with price, while an oscillator keeps its own scale whatever it is fed. Combining is explicit: any combination, at least two different indicators, or "must include" up to three named indicators, plus conditions per rule 1-3. A search over 250,000 rules (2M tests) is refused before it starts with what to change; the plan shows the size as the picker is edited. Results show each rule in words. The picker's state is autosaved as a research document and syncs across devices. Divergence is now offered only for oscillator scales, since a divergence between price and volume or ATR has no accepted reading. The Research page also no longer dead-ends an account with no saved strategy: it opens on Relationships, which needs none.
